Projet: cc-app-backend-v2-monolitic
Type: Backend fintech en monolithe modulaire (Spring Boot + PostgreSQL)

Stack technique:
- Java 21, Spring Boot 3.5.11
- Spring Web, Security, Validation, Data JPA, Actuator
- Flyway (migrations SQL)
- MapStruct, Lombok
- OpenAPI/Swagger (activable en dev)
- Firebase Admin (authentification)
- Build/deploy: Maven + Docker + GitLab CI

Modules existants et état fonctionnel:

1) Identity (fonctionnel)
- Sync utilisateur via token Firebase (ID token valide)
- Création/upsert user, device, session
- Onboarding profil
- Lecture profil courant (/me)
- Gestion devices (register/block)
- Rotation refresh token + révocation session
- Endpoint interne pour blocage compte utilisateur

2) Subscription (fonctionnel côté backend)
- Liste des plans actifs par pays
- Initiation d’abonnement:
  - vérifie user actif
  - crée opération INITIATED (idempotency key)
  - appelle client Jawupay
  - associe pspReference à l’opération
- Limite actuelle: client Jawupay est un stub (pas une vraie intégration externe)

3) PSP callback (fonctionnel avec sécurité)
- Endpoint callback public
- Vérifications:
  - rate limit par IP (in-memory)
  - anti-replay (nonce unique + fenêtre timestamp)
  - signature HMAC
- Si callback SUCCESS/CONFIRMED:
  - confirmation opération
  - posting comptable automatique (double entrée)

4) Accounting / Ledger (fonctionnel)
- Gestion des opérations (INITIATED -> CONFIRMED)
- Posting comptable:
  - écriture équilibrée DEBIT/CREDIT
  - création accounting_events + ledger_entries
  - mise à jour snapshots de solde
- Reconciliation:
  - import batch PSP
  - matching vs opérations confirmées
  - génération d’ajustements comptables en cas d’écart
  - endpoint de synthèse settlement par devise

Base de données (Flyway):
- V1: identity (users, profiles, devices, sessions)
- V2: accounting (operations, events, ledger, snapshots, reconciliation_records)
- V3: subscription_plans
- V4: psp_callback_events
- V5: hardening (tables append-only pour events/ledger) + seed plans subscription

Sécurité actuelle:
- /internal/** protégé par X-API-KEY
- Endpoints publics:
  - GET /subscriptions/plans
  - POST /psp/jawupay/callback
  - actuator health/info
- Le reste requiert authentification Bearer
- Mode dev: token de type "Bearer <Firebase ID token>" requis

Qualité / tests:
- Tests unitaires présents sur:
  - OperationService
  - AccountingPostingService
  - RefreshTokenService
- Pas de tests d’intégration web/security/repository
- Pas de tests end-to-end callback -> ledger

Points d’attention techniques avant ajout de modules:
- Secrets sensibles présents dans les properties (mail password, DSN, partner API keys)
- Fichiers credentials Firebase présents dans le repo
- .gitignore n’ignore pas target/.idea (artefacts générés suivis)
- Config hétérogène/legacy (propriétés historiques encore présentes)
- spring.jpa.hibernate.ddl-auto=update en dev/prod (risque de drift avec Flyway)
- client PSP actuellement mocké/stubé

Objectif demandé:
- Ajouter de nouveaux modules et modifier certains modules existants
- Préserver cohérence DDD modulaire actuelle (controller/service/repository/entity + migration Flyway)
- Renforcer couverture de tests avant changements majeurs
