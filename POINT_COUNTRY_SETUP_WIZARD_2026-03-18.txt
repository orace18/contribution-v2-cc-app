POINT DE SITUATION — Country Setup Wizard (QA / Polish)
Date: 2026-03-18

Contexte
- Le moteur Country Configuration fonctionne techniquement.
- Objectif de cette passe: rendre le parcours exploitable par des utilisateurs opérations non techniques.

Livraison réalisée (Backoffice)

1) Wizard guidé 8 étapes
- Step 1: General
- Step 2: Accounting
- Step 3: Membership
- Step 4: MLM & Gains
- Step 5: Financing
- Step 6: Payment
- Step 7: Risk & Guarantee
- Step 8: Review & Activate

2) Règles UX demandées
- Blocage du passage à l’étape suivante si invalide.
- Affichage clair des erreurs de validation par étape.
- Auto-save draft entre étapes (stockage local par pays).
- Score de readiness wizard calculé en live.

3) Écran Review & Activate
- Résumé global par section.
- Statut par section: COMPLETE / MISSING / RISKY.
- Mise en évidence des manques et signaux de risque.
- Action “Edit section” pour revenir directement sur la section à corriger.

4) Safe activation conservée
- Flux de sécurité inchangé avant validation:
  1. Review
  2. Password re-entry
  3. 2FA
  4. reasonForChange
- Activation wizard branchée sur les APIs existantes (upsert séquentiel par config type), sans nouveau contrat backend.

5) Empty state entry
- Si aucun pays configuré:
  - Message onboarding explicite.
  - CTA visible: “Start country setup”.

6) No JSON exposure
- Aucun JSON brut exposé à l’utilisateur dans le parcours wizard.
- Interface basée sur formulaires métier + sélecteurs.

Non-régression / vérification
- Build front exécuté avec succès:
  npm run -s build
- Aucun changement backend requis pour ce lot wizard.
