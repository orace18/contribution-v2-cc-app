API CONTRACT - MOBILE / FRONTEND
================================

Base response envelope
----------------------
All endpoints below return:
{
  "success": true|false,
  "message": "string",
  "data": { ... } | null,
  "timestamp": "ISO-8601 instant"
}

Auth: Bearer token required for all listed endpoints.
Note: runtime may include server context-path (/cc-app-backend) depending on environment config.

2) CHAT PRODUCTION ENDPOINTS
============================

2.1 Send message
----------------
POST /chat/messages

Request:
{
  "recipientAccountHolderId": "uuid",
  "content": "string (required, max 2000)",
  "channel": "string (optional, max 32, defaults IN_APP_CHAT)",
  "clientMessageId": "string (optional, max 128, idempotency key)"
}

Response data:
{
  "id": "uuid",
  "senderAccountHolderId": "uuid",
  "recipientAccountHolderId": "uuid",
  "conversationId": "uuid",
  "content": "string",
  "channel": "string",
  "clientMessageId": "string|null",
  "messageStatus": "SENT|DELIVERED|READ",
  "deliveredAt": "ISO-8601 offset datetime|null",
  "readAt": "ISO-8601 offset datetime|null",
  "createdAt": "ISO-8601 offset datetime"
}

2.2 Paginated messages
----------------------
GET /chat/messages?conversationId={uuid}&before={ISO_OFFSET_DATETIME}&limit={int}

Query params:
- conversationId: required
- before: optional cursor timestamp
- limit: optional, service caps max value

Response data:
{
  "conversationId": "uuid",
  "messages": [ ChatMessageResponse... ],
  "nextBefore": "ISO-8601 offset datetime|null"
}

Pagination usage:
- First call: omit before
- Next call: send before=nextBefore from previous response
- Stop when nextBefore is null

2.3 Mark delivered
------------------
PATCH /chat/messages/{messageId}/delivered

Response data: ChatMessageResponse (same shape as send)

2.4 Mark read
-------------
PATCH /chat/messages/{messageId}/read

Response data: ChatMessageResponse (same shape as send)


3) MLM ENDPOINTS
================

3.1 Placement
-------------
POST /mlm/placements

Request:
{
  "accountHolderId": "uuid",
  "sponsorAccountHolderId": "uuid"
}

Response data:
{
  "accountHolderId": "uuid",
  "sponsorAccountHolderId": "uuid",
  "placedUnderAccountHolderId": "uuid",
  "directChildrenCount": 3,
  "sponsorTeamSize": 12,
  "placedAt": "ISO-8601 offset datetime"
}

Rules enforced by backend:
- each user has one sponsor
- max 5 direct children per node
- depth unlimited
- placement uses first available leg in sponsor subtree

3.2 Upline
----------
GET /mlm/{accountHolderId}/upline

Response data:
[
  {
    "accountHolderId": "uuid",
    "level": 1,
    "firstName": "string",
    "lastName": "string",
    "linkedAt": "ISO-8601 offset datetime"
  }
]
